# AI Instructions

Apply these rules to all changes in this repository.

## Coding Standards

- Follow `SOLID` principles.
- Follow `DRY` principles.
- Prefer small, focused, maintainable changes.
- Keep naming clear, professional, and consistent with the existing codebase.
- Avoid duplicate logic; extract shared code when it improves readability.
- Do not introduce unnecessary abstractions.

## Working Style

- Be professional and concise.
- Minimize token usage.
- Do not produce long explanations unless explicitly requested.
- Before changing code, understand the related files and existing patterns.
- Preserve the current project structure unless a structural change clearly improves maintainability.

## Response Style

- After making changes, explain what changed and why in a short, clear summary.
- Mention any risks, assumptions, or follow-up steps only if they matter.
- Prefer high-signal output over verbose walkthroughs.

## Project Notes

- For `mobile/`, use Expo SDK 56 compatible patterns.
- Respect any more specific instructions in nested `AGENTS.md` or equivalent files.
